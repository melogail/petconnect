## Pipeline step shape
Each step is a class with `handle($context, Closure $next): mixed` that mutates or reads a typed context object and returns `$next($context)`. Steps never know about their neighbours or about HTTP. A step that must abort the flow throws a domain exception rather than returning early with a different type.

A step also never reads `config()`. Every tunable a flow needs is resolved once by the Action that runs it and arrives on the context (see `HomeFeedContext::$perPage` / `$commentPreview`, `HomeFeedFilters::$ageCeiling`, `UpdatePetContext::$maxGalleryImages`), so a step can be driven with any value without touching the configuration repository.

**A domain abort may extend `ValidationException` when — and only when — the abort really is a field-level input problem.** `Exceptions\Pets\PetTaxonomyNotFound` does: a category or breed that vanished between validation and persistence is a stale form control, and Laravel already turns `withMessages([$field => ...])` into a 422 with `message`/`errors` for an API client and a redirect-back-with-errors for a form post. A pure domain exception plus a `render` mapping would be two more moving parts for byte-identical behaviour. The trade-off is real and accepted, not overlooked: `ValidationException` declares `response`, `status` and `redirectTo`, so such an exception is not HTTP-free — the *step* stays HTTP-free, which is the property that matters. An abort that is not attributable to a submitted field (a gateway refused, a lock was not acquired, an invariant broke) gets its own exception class and does not borrow this base to buy a free status code.

## An Action runs the pipeline; extract a second Action only when it earns its keep
Controllers never build a Pipeline. The entry point is an Action in app/Actions/{Domain}/ that constructs the typed context, runs Illuminate\Pipeline\Pipeline through an explicit step list, and returns the result from then() (see CreatePet, UpdatePet, ListHomeFeedPets).

**Default to writing the work inline in the step.** Extract it into a single-purpose Action only when one of these is true:
- a second caller needs it (Actions\Pets\AttachFeaturedImage is used by both the create flow's AttachFeaturedImage and the update flow's ReplaceFeaturedImage), or
- it is genuinely worth exercising without the pipeline — non-trivial branching or arithmetic you want to pin down on its own.

A one-caller Action behind a one-caller step is a file and a hop for no testability gain: the step is already a small class with one public method, and a test that drives the pipeline covers it. This used to read "a step that performs real work delegates to an Action of the same name", which was followed 5 times out of 21 and, taken literally, would double the class count of every vertical.

## Flow-specific steps hint their own context; only Shared/** hints the abstract
Steps used by more than one flow go in app/Pipelines/{Domain}/Shared/ and type hint the shared abstract context (PetAttributeContext), which is what lets the create and update flows reuse the Normalize* steps unchanged.

**A step in a flow directory type hints that flow's context, never the abstract one.** This is the invariant that makes a shared abstract context safe: Update\ReplaceFeaturedImage deletes the listing's existing cover photo, so hinting PetAttributeContext would let it accept a CreatePetContext and delete a photo that cannot exist. Narrow the hint even when the step only reads inherited members — the type is the statement of which flows may run it.

## Never name a flow directory the same as a class in app/Actions/{Domain}
`App\Actions\Pets\CreatePet` (a class) and `App\Pipelines\Pets\CreatePet` (a namespace) were the same identifier, so every import read ambiguously. Flow directories are named for the flow, not for the Action that runs it: `Pipelines/Pets/Create`, `Pipelines/Pets/Update`, `Pipelines/Pets/BuildHomeFeed`.

That rename fixed the **directory** collision only. A step and the Action it delegates to may still share a class name — `Pipelines/Pets/Create/AttachFeaturedImage` opens with `use App\Actions\Pets\AttachFeaturedImage as AttachFeaturedImageAction;` — which is tolerated, not solved. If you are naming a new step that delegates to an Action, prefer a verb the Action does not use (`UploadFeaturedImage` for a step calling `AttachFeaturedImage`) and skip the alias.
