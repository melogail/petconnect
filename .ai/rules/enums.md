# Enums

> **`.ai/rules/app.md` also applies to this path and must be read too.** Its `app/**` glob
> covers everything covered here; this file adds to it rather than replacing it. Do not stop at
> the first row of the index that matches — the index is regenerated by `record-rule` on every
> write, so its ordering and wording carry no meaning.

## Enums: snake_case backing values, TitleCase cases, and morph-alias whitelists
Backing values are machine-safe lowercase snake_case (`hate_speech`, `pending`, `adoption`); human text comes from `label()`. Never store display strings in the DB — the legacy enums did and it is deliberately not ported. Case names are TitleCase, backing type is always explicit `: string` (ListingType was int-backed in legacy while its column was a string — fixed).

`Commentable`, `Reportable`, `Reviewable` are the whitelists for the polymorphic `*_type` inputs. Controllers/Form Requests must resolve a morph target through the enum's `modelClass()` / `findOrFail()`, never from a raw class name in the request or URL. Their backing values are exactly the morph map aliases registered in `AppServiceProvider::configureMorphMap()` — keep the two in sync.

## options() comes from HasOptions; label() is untranslated and known to be
A backed enum that feeds a select control uses `App\Concerns\HasOptions` for `options()` — do not hand-write another copy. Ten enums carried a byte-identical `array_map(fn (self $case) => ['value' => ..., 'label' => ...], self::cases())` before it was extracted. The trait declares `abstract public function label(): string`, so the composing enum only supplies what differs.

Known gap, deliberately open: every `label()` returns hardcoded English with no `__()`, in an app whose own rules cite Arabic user input as a design driver. Do not localise one enum in passing — it is a change to all of them plus every consumer that already treats the label as a display string, and half a migration is worse than none. Raise it as its own piece of work.

Enums hold domain vocabulary, not presentation. `PetStatus::color()`, `ListingType::style()` and `ReportStatus::style()` returned Tailwind class strings, had zero callers, and never reached the frontend (`options()` emits only `value` and `label`); all three were removed. Badge styling belongs in the Vue component that renders the badge — the legacy UI already hardcodes its badge classes in `PetHeader.vue`, `PetListingInfo.vue` and `PetHealthInfo.vue`, so nothing is lost when those pages are ported. Do not add a `color()`, `style()`, `icon()` or `badge()` method to an enum.
